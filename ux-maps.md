# Fa 2.0 — три карты UX

Этап: **информационная архитектура и пользовательские потоки**. Документ
фиксирует модель; рядом находится кликабельный SPA-wireframe (`index.html`) для
desktop, mobile keyboard и Fold. Это не production visual design.

## 1. Что уже зафиксировано

- Основной паттерн должен быть понятен как у мессенджера: список диалогов,
  favourites/pinned, поиск, последнее сообщение и статус активности.
- **Агент постоянный**: у него есть имя, память, настройки, задачи и основной
  непрерывный диалог. Перезапуск приложения или модели не создаёт нового
  агента.
- **My Network — дом агента по умолчанию**: каждый добавленный постоянный агент
  сразу становится участником пользовательской сети. Не нужно отдельно
  выбирать Local/Network или вручную подключать его к первой сети.
- **Канал — способ группировать агентов**: и пользователь, и агент могут
  создавать каналы и собирать в них участников сети под тему, проект или задачу.
- **Quick chat существует отдельно от агента**: это лёгкий разговор без
  обязательного создания постоянной личности. Его можно архивировать, связать
  с агентом или превратить в нового агента.
- `session` — технический механизм запуска, хранения и восстановления. В UX не
  должно быть списка `Sessions` и названий вроде `Oct 26 09:50`.
- Local и Network не должны быть двумя переключаемыми режимами всего
  приложения.
- Apps доступны **из composer и собственного раздела**, без лишнего Open app в
  глобальном Quick actions. На desktop App открывается панелью, разворачивается
  на весь контент или закрепляется; на mobile получает полноценный экран.
- По умолчанию контент важнее chrome: минимум постоянных header'ов, никаких
  вложенных drawer поверх drawer и никакого всегда открытого пустого Apps.

### Решения после кликабельного review

- **A / messenger-like — основной кандидат.** C остаётся сравнением с
  Activity-first подходом, а не обязательным вторым режимом продукта.
- **Mobile quick actions живут в floating `+`** над bottom navigation. Внутри —
  New chat, Add agent, Create channel и Networks. New task запускается из
  конкретного агента; Apps имеет собственный раздел и contextual composer action.
- **New chat — один compose-flow вместо предварительного выбора типа.** Поле To
  принимает local и network agents: 0 получателей = local Quick chat, 1 = endless
  direct, 2+ = новая группа в My Network с необязательным именем.
- **Смешанная группа не расширяет network membership.** Внешний агент явно
  показан в compose и получает доступ только к созданной группе, не к другим
  чатам и не ко всей My Network.
- **Apps разделены по намерению:** `My Apps` — установленные и running widgets,
  `My Boards` — личные многовиджетные раскладки, `Widget Store` — обнаружение и
  установка новых виджетов. Store не смешивается с уже установленными Apps.
  `New app` создаёт custom app в My Apps, а не в Store и не в Boards.
- **Fold получает правый action rail и центральный splitter.** Rail содержит
  New / Search / Apps / Activity / More; splitter между списком и контентом
  перетаскивается, а основной контент не уходит под rail.
- **Модель меняется в контексте агента**: компактный model control в composer,
  mobile chips `Model / Apps / New chat` без обязательного `/` и slash-подсказки
  как дополнительный клавиатурный путь. Смена модели не создаёт session или agent.
- **Компактный Create / manage** рядом со списком и в Fold rail объединяет New
  chat, New channel, Networks и управление существующими channels/networks.
  Networks предлагает отдельные Create и Join по invite/code.
- **Channel invite — самостоятельный flow:** QR для мобильного агента или CLI
  `fa agent join …`, объяснение шагов, expiry и явный scope `This channel only`.
  Приглашение не даёт доступ ко всей network; подключение подтверждает владелец.
- **Empty state — проверяемый экран, а не отсутствие данных ради demo.** Empty
  preview показывает first-run Chats, Inbox, Apps и Boards, не удаляя populated demo.
- Mobile chat использует округлые сообщения и floating Liquid-Glass-like composer
  как UX-направление; keyboard поднимает composer и bottom-sheet без overlap.

## 2. Общая модель объектов

| Объект | Значение для пользователя | Что видно в UX |
|---|---|---|
| **Agent** | Постоянный собеседник и исполнитель с общей памятью | Имя, назначение, статус, основной диалог, задачи, routines, Apps |
| **Quick chat** | Быстрый разовый разговор | Автоматическое название по теме, возраст/статус, действия Archive / Link to agent / Become agent |
| **Network** | Группа людей и агентов с общими каналами и правами; `My Network` существует у пользователя по умолчанию | Название, участники, каналы, уведомления; конкретная роль в навигации зависит от варианта ниже |
| **Channel** | Группа людей и/или агентов для темы, проекта или задачи | Название, network, creator, назначение, участники, lifetime, непрочитанное |
| **Topic / branch** | Навигация внутри истории агента | Не новая сессия и не новый агент; создаётся по желанию или автоматически |
| **Task / routine** | Работа агента вне текущего сообщения | Running / waiting / done / failed, результат и переход к связанному диалогу |
| **My Apps** | Установленные интерактивные инструменты и виджеты пользователя | Favorites, Recents, Running; явный контекст запуска |
| **My Boards** | Личные раскладки из нескольких виджетов | Board cards, состав виджетов, открытие независимо от чата |
| **Widget Store** | Каталог доступных виджетов, отдельный от установленных | Категории, описание, Add → My Apps, Open для установленного |
| **Activity** | Входящие события, требующие внимания | Mentions, approvals, завершённые задачи, ошибки, сообщения агентов |

### My Network и добавление агента

`My Network` автоматически существует у каждого пользователя. Это домашняя сеть
для его агентов, а не ещё один сервер, который нужно вручную создать.

```text
Add agent
  → Имя / назначение / capabilities
  → Создаётся постоянный Agent identity
  → Agent автоматически становится участником My Network
  → Сразу доступен в Members и Search
  → Можно писать ему, поручать задачи и добавлять в каналы
```

```text
My Network
├── Members
│   ├── Владелец
│   └── Все добавленные пользователем агенты, если их не удалили явно
├── Channels
│   ├── Каналы пользователя
│   └── Каналы, созданные агентами
├── Apps / capabilities, разрешённые в сети
└── Settings / permissions / notifications
```

- Дополнительные networks подключаются отдельно. Добавление агента в
  `My Network` **не даёт ему автоматического доступа** к `client-acme`,
  `ai_conf` или любой другой сети.
- В `My Network` агент по умолчанию может создавать каналы и приглашать в них
  других участников `My Network` без подтверждения каждого действия. Владелец
  может ограничить это разрешение; в остальных networks действуют их правила.
- Участие в `My Network` не означает доступ ко всем private channels: в такие
  каналы агента всё равно приглашают явно.
- Удаление агента из `My Network` — отдельное явное действие; оно не должно
  незаметно удалять identity, основной диалог или историю.
- Quick chat не создаёт network membership. Действие `Become persistent agent`
  запускает тот же поток: новый агент сразу попадает в `My Network`.

### Каналы как группы агентов

Отдельный объект `Group` на этом этапе не нужен: **группа агентов — это канал с
составом участников и назначением**. Такая группа может быть постоянной
(`# research-team`) или временной (`# release-260-audit`, связанной с задачей).

```text
User или Agent → Create channel
  → Network: My Network по умолчанию, либо текущая доступная network
  → Название и назначение
  → Выбрать людей и агентов из этой network
  → Persistent или Task-bound
  → Канал появляется в Directory и в навигации выбранного UX-варианта
```

Пример автономной группировки:

```text
Release Manager получает задачу «Проверить релиз»
  → создаёт # release-260-audit в My Network
  → добавляет Code Reviewer, Test Runner и Researcher
  → связывает канал с исходной задачей
  → участники обмениваются результатами в канале
  → после завершения канал можно автоматически архивировать, не удаляя историю
```

Правила для каналов, созданных агентами:

- В UX видны `Created by <agent>`, назначение и связанная задача.
- Владелец `My Network` может найти такой канал и управлять им, но не получает
  уведомление о каждом сообщении, если сам не участвует или его не упомянули.
- Агент может свободно группировать участников внутри доступной ему сети, но не
  может выдать им права выше собственных.
- Добавление агента из другой network или создание cross-network канала требует
  явного разрешения владельца/правила сети.
- Task-bound канал архивируется по завершении задачи; постоянный канал остаётся
  вручную закрепляемой командой.

### Общее правило Apps

Apps не принадлежат технической сессии. Каталог глобальный, а запуск может
получить контекст: `Mail Reader → My Network`, `Files → yoclip-studio`,
`Preview → Quick chat «Landing page»`. Контекст виден и переключается внутри
App. Пользователь может закрепить App независимо от текущего диалога; выбор
панели/fullscreen запоминается отдельно для каждого устройства.

### Общие quick actions

- **Search / Command** — найти агента, канал, сеть, App или действие.
- **Quick chat** — начать разговор без настройки агента.
- **New agent** — создать постоянного агента; он сразу попадает в `My Network`.
- **Open app** — favorites и последние Apps доступны сразу, весь каталог — по
  запросу.
- **New task** — поручить работу выбранному агенту.
- **Create channel / Group agents** — собрать участников сети; доступно и
  пользователю, и агенту с соответствующим разрешением.
- **Create / join network** — отдельное действие, не нужное для добавления
  обычного агента.

Внутри диалога: `Open app`, `Files`, `Tasks`, `Agent details`, `Pin`.
Для сообщения: `Reply`, `Create task`, `Send to agent`, `Open in app`.

## 3. Общий стресс-тест для всех вариантов

Предположим, у пользователя уже есть:

- **32 агента и 10 каналов в My Network**: Fa, Mail Reader, Researcher, Code
  Reviewer, Release Manager, Finance, Home, Travel и другие. Все агенты попали
  туда автоматически при добавлении; часть каналов уже создана ими самими.
- **14 quick chats**, из которых только 4 активны сейчас.
- `istin-network`: 18 агентов, 12 каналов.
- `yoclip-studio`: 9 агентов, 8 каналов.
- `ai_conf`: 40 агентов, 20 каналов.
- `home-lab`: 7 агентов, 6 каналов.
- `client-acme`: 12 агентов, 9 каналов.

Итого **6 networks**: домашняя `My Network` и пять дополнительных. Среди 65
каналов 17 созданы агентами, включая 9 task-bound каналов для конкретных задач.

Если показать всё одним деревом, получится **197 строк** до раскрытия задач и
Apps. Поэтому ни один вариант не должен показывать полное дерево одновременно.
Проверяем каждую модель на этом объёме.

# Вариант A — Fa Messenger

## Главная идея

**Диалог — основная единица навигации.** Агенты, quick chats и каналы живут в
одном messenger-like списке. Network — это папка/фильтр и источник каналов, а
не отдельный режим приложения. `My Network` — стартовая папка всех добавленных
агентов; каналы, которые агенты создают для группировки, появляются в том же
общем списке по активности.

Это самый близкий вариант к понравившимся референсам.

## Карта навигации

После UX review навигация A упрощена: три основных раздела, один вход для
создания и один вход для поиска.

```text
Fa
├── Шапка списка: [Fa profile] [Search ⌘K] [New]
│   ├── Search — поле в шапке, открывает тот же глобальный поиск, что Cmd/Ctrl K
│   ├── New (desktop/Fold) или floating New (mobile) — единственный create-вход:
│   │   New chat · Add agent · New channel · Networks · Manage channels/networks
│   └── Profile / settings — Networks, All agents, UX notes, Reset demo
├── Chats — стартовый раздел
│   ├── Filter chips: All · Unread · Agents · Channels · [All networks ▾]
│   │   ├── All — Pinned + Recent (агенты, каналы, quick chats)
│   │   ├── Unread — только непрочитанное
│   │   ├── Agents — бывший Directory/Agents: строка «Add agent» сверху,
│   │   │   затем все агенты, включая тех, с кем ещё нет переписки
│   │   ├── Channels — все каналы, активные и Archived
│   │   └── Network chip — показывается, только если сетей больше одной
│   └── Строка = 2 линии: avatar(+working dot) · title [tag network|task] · time
│                          preview · unread badge
├── Activity
│   ├── Needs you
│   ├── Running
│   └── Results / Later
├── Apps
│   ├── My Apps — installed / favorite / running
│   ├── My Boards — personal widget layouts
│   └── Widget Store — discover / install
└── Networks (не вкладка) — из New → Manage networks, Profile → Networks,
    network chip → Manage networks и Details → Open <network>
```

Network-тег в строке показывается только вне `My Network`, поэтому несколько
`#general` различимы без шумной третьей строки. Автор канала перенесён в
Details.

## Внутри постоянного агента

```text
Header: [←] [avatar] Mail Reader / «Online» | «Working…»          [ⓘ Details]
Channel header: #research-team / «4 agents» (+ «· Task», «· <network>»)
Composer: [+ Attach: Files, Apps] [Message Mail Reader] [Model chip*] [Send]
          * Model только для локальных агентов и quick chats; /model, /apps, /new
            подсказываются при вводе «/»
Messages: bubbles — свои справа, агента слева; системные события одной тихой строкой

Agent: Mail Reader
├── Main conversation — непрерывный по умолчанию
│   ├── Темы и точки в истории
│   └── Optional branches
├── Tasks / routines
├── Memory / files
├── Apps, связанные с агентом
├── Networks
│   ├── My Network — домашняя сеть по умолчанию
│   └── Дополнительные memberships
├── Channels: участие и созданные агентом группы
└── Details / permissions / notifications
```

Пользователь не нажимает `New session`. Новое сообщение агенту продолжает его
основной диалог. Отдельная тема создаётся только тогда, когда сам пользователь
хочет ответвление, либо когда система предлагает пометить новую тему для
навигации.

## Quick chat

```text
New (header / mobile floating New)
  → New chat без получателей → Quick chat
  → Первое сообщение
  → Автоматическое название по теме
  → Активный чат в Recent
       ├── Продолжить позже
       ├── Archive
       ├── Link to agent
       └── Become persistent agent → автоматически в My Network
```

Quick chats не засоряют постоянный список: неактивные уходят в архив по правилу
пользователя. При этом архив остаётся доступен через поиск. При превращении в
агента история quick chat становится началом его основного диалога, а membership
в `My Network` создаётся автоматически.

## Как модель выдерживает 197 потенциальных строк

- В `Recent` показываются только недавние, непрочитанные и работающие диалоги,
  а не все существующие контакты.
- Все агенты и 65 каналов доступны через чипы `Agents` / `Channels` и
  глобальный поиск; отдельной вкладки Directory больше нет.
- `Pinned` ограничен разумным коротким списком; остальное остаётся в папках.
- `My Network` содержит домашних агентов и их постоянные команды; временные
  task-bound каналы показываются в Recent только пока активны.
- Папка `ai_conf` свёрнута и показывает суммарный unread badge. Внутри неё
  сначала идут `# mentions`, активные каналы и недавние агенты.
- Пользовательские папки позволяют собрать, например, `Work`, `Home` и
  `Background agents`, не меняя реальную структуру networks.
- Каналы с режимом mute не появляются в общем Recent только из-за новых
  сообщений; mentions продолжают попадать в Activity.

## Apps

```text
Диалог → composer + (Attach) → Files / Apps
Раздел Apps (вкладка, bottom nav, Fold rail)
  → Apps
       ├── Favorites
       ├── Recent
       └── All apps
  → Open in side panel / fullscreen
  → Optional: Keep pinned

Во время выбора другого диалога
  → Закреплённый App остаётся
  → Его контекст не меняется молча
```

## Mobile

- Основные разделы: **Chats / Activity / Apps**. `More` удалён: Networks,
  UX notes и Reset demo живут в profile/settings (`Fa` в шапке).
- Шапка списка одна: `Fa` · заголовок `Chats` · поле Search; ниже чипы фильтров.
  Create — только floating New (FAB), без дублирующей кнопки в шапке.
- Диалог — отдельный fullscreen-маршрут: назад ведёт ровно на один уровень.
- Переключателя Local/Network нет; network — фильтр в списке Chats.
- Floating New открывает: New chat, Add agent, New channel, Networks, Manage.
  New task — в Details агента. Новый агент сразу попадает в `My Network`.
- Чипы над composer контекстные: `Model: Auto` только у локальных агентов,
  `Apps` всегда; `New chat` внутри диалога не показывается.
- Apps открываются fullscreen; Running apps доступны через Apps и Activity.
- Composer существует только внутри диалога, а не на экранах каталога и Apps.

## Сильные стороны

- Минимальный порог входа: понятно любому пользователю мессенджеров.
- Быстрый доступ к нужному диалогу без выбора сети заранее.
- Постоянный агент и quick chat естественно соседствуют.
- Одинаково хорошо работает и с агентами `My Network`, и с созданными ими
  каналами/командами.

## Риски

- При очень активных networks общий Recent может стать шумным.
- Без auto-archive и digest временные каналы, созданные агентами, могут
  переполнить Recent.
- Папки и политика уведомлений становятся обязательной частью UX.
- Структура прав и membership менее наглядна, чем в Space-first модели.

# Вариант B — Fa Spaces

## Главная идея

**Network — рабочее пространство.** Сначала выбирается `My Network` или другая
network, затем пользователь видит только её агентов, каналы, quick chats и
доступные Apps. `My Network` выбрана изначально и уже содержит всех добавленных
агентов. Глобальные Activity, Search и Apps остаются доступны без смены
пространства.

Модель ближе к Slack/Discord, но без обязательного постоянного второго и
третьего sidebar.

## Карта навигации

```text
Fa
├── Space switcher
│   ├── My Network — default home всех новых агентов
│   ├── Pinned networks
│   ├── Recent networks
│   └── All networks / Create / Join
│
├── Current space: My Network или выбранная network
│   ├── Home / unread
│   ├── Agents
│   │   ├── Favorites
│   │   ├── Active now
│   │   └── All in this space
│   ├── Channels
│   │   ├── Mentions / unread
│   │   ├── Persistent teams и каналы пользователя
│   │   ├── Agent-created / task-bound
│   │   └── All channels
│   ├── Quick chats
│   └── Space settings / members / permissions
│
├── Global Activity
│   └── Все пространства с фильтром по space
├── Global Apps
│   ├── Running / Favorites / Recent
│   └── Catalog + ограничения текущего space
└── Settings
```

## Постоянный агент внутри Space

У агента остаётся один постоянный identity и его основной диалог. При
добавлении он автоматически появляется в `My Network / Agents` — пользователю
не нужно предварительно выбирать space. Список `Agents` внутри любой network —
это способ найти агента и увидеть его роль в этом пространстве, а не причина
создавать новую сессию.

```text
Agent identity
├── Global main conversation
├── Tasks / routines / Apps
├── Network memberships
│   ├── My Network: домашняя сеть по умолчанию
│   ├── istin-network: роль, права, каналы
│   ├── ai_conf: роль, права, каналы
│   └── client-acme: роль, права, каналы
└── Channels, которые агент создал для группировки участников
```

История в канале принадлежит каналу. Личный основной диалог агента не дублируется
в каждой сети. Канал, созданный агентом для группировки других агентов, живёт
внутри выбранной network и не появляется в остальных spaces. Если network
требует изолированную память, это должен быть явно обозначенный отдельный agent
instance, а не незаметно созданная сессия.

## Как модель выдерживает 197 потенциальных строк

- В Space switcher одновременно видны `My Network`, pinned и несколько recent
  networks, а не весь список.
- `My Network` сразу содержит 32 домашних агента и их каналы; это не пустой
  space, который нужно наполнять вручную.
- При выборе `ai_conf` пользователь работает только с её 40 агентами и 20
  каналами; содержимое остальных сетей скрыто.
- Внутри большой network Agents и Channels не развёрнуты одновременно:
  ежедневный Home содержит Favorites, Unread и Active now.
- Двадцать каналов `ai_conf` группируются по смыслу: `General`, `Projects`,
  `Support`, `Automations`, `Archive`.
- Непрочитанное в других networks видно как badge на Space switcher и в
  глобальном Activity — переключаться ради проверки каждой сети не нужно.
- Для десятков networks работают поиск, pinning, folders и скрытие muted spaces.

## Apps

Apps имеют два уровня:

- **Global Apps** — личные инструменты, доступные всегда.
- **Space apps** — установленные или разрешённые внутри network.

Quick action показывает оба уровня и явно подписывает контекст. Закреплённый
глобальный App не исчезает при смене space. Space App можно открыть только при
доступном соответствующем пространстве.

## Mobile

- Основные разделы: **Chats / Activity / Apps / More**.
- Текущий space выбирается на корневом экране Chats; внутри диалога переключатель
  пространства не занимает место.
- Смена space меняет содержимое списка, но не открывает дополнительный drawer.
- Global `+` предлагает Quick chat, Group agents / Create channel и другие
  действия, допустимые в текущем space. `New agent` всегда создаёт агента в
  `My Network`; добавление в текущую дополнительную network — отдельный выбор.
- Apps и диалоги открываются fullscreen; назад возвращает в исходный space и
  сохраняет позицию списка.

## Сильные стороны

- Самая ясная модель для командной работы, каналов и прав доступа.
- `My Network` даёт предсказуемый дом каждому новому агенту, а каналы явно
  показывают созданные им команды внутри каждого пространства.
- Большие networks не смешиваются друг с другом.
- Понятно, какие Apps и агенты доступны в конкретном окружении.
- Хорошо масштабируется на десятки networks.

## Риски

- Для простого разговора со своим агентом появляется лишний уровень выбора.
- Один и тот же агент встречается в нескольких spaces; нужно последовательно
  объяснять, что это тот же identity.
- Пользователю, который работает только в `My Network`, переключение spaces
  может оказаться лишним уровнем навигации.

# Вариант C — Fa Pulse

## Главная идея

**Activity — стартовый экран.** Пользователь не просматривает сотни агентов и
каналов: система показывает только то, что требует внимания, уже работает или
принесло результат. Остальное доступно через Conversations, Directory и Search.

Это модель центра автономных агентов, а не классического мессенджера. Каждый
новый агент всё равно автоматически принадлежит `My Network`; если он создаёт
канал и собирает команду, канал появляется в Running/Activity по событиям, а не
как ещё одна постоянная строка перед пользователем.

## Карта навигации

```text
Fa
├── Inbox — стартовый раздел
│   ├── Needs you
│   │   ├── Mentions / direct questions
│   │   ├── Approvals
│   │   └── Failed / blocked tasks
│   ├── Running
│   │   ├── Agents
│   │   ├── Tasks
│   │   └── Apps
│   ├── Results
│   └── Later / scheduled
│
├── Conversations
│   ├── Pinned / recent
│   ├── Agents / quick chats / channels
│   └── Filters: My Network, other networks, type, status
│
├── Agents
│   ├── Favorites / active
│   ├── My Network — все добавленные по умолчанию
│   ├── All agents
│   └── Agent home
│       ├── Main conversation
│       ├── Tasks / routines / schedule
│       ├── Memory / files / Apps
│       ├── Network memberships
│       └── Channels, созданные агентом
│
├── Apps
│   ├── Running / Favorites / Recent
│   └── Catalog
├── Networks
│   ├── My Network — домашние агенты и их каналы
│   ├── Other memberships / channels / notification policy
│   └── Administration
└── Settings
```

## Поток пользователя

```text
Agent работает в фоне
  → событие попадает в Inbox
  → пользователь видит результат или проблему
  → открывает связанный диалог только при необходимости
  → отвечает / меняет задачу / запускает App
  → возвращается в Inbox
```

```text
Agent создаёт task-bound канал в My Network
  → добавляет нужных агентов из My Network
  → канал и связанная задача видны в Running
  → владелец получает только итог, mention или блокирующее событие
  → после завершения канал архивируется и остаётся доступным через поиск
```

Quick chat появляется в Inbox только пока активен или требует ответа. Затем он
архивируется. Network служит фильтром и источником событий, но не обязательным
уровнем навигации. `My Network` — фильтр по умолчанию для собственных агентов;
их не нужно вручную подключать к сети перед первой задачей.

## Как модель выдерживает 197 потенциальных строк

- Стартовый экран показывает не 197 объектов, а, например, 7 событий: 2
  approvals, 1 failed task, 2 mentions и 2 результата.
- 32 агента `My Network` и 40 агентов `ai_conf` не занимают отдельные строки,
  если ничего не требуют.
- 65 каналов, включая созданные агентами команды, сворачиваются в digest по
  network; важные mentions и блокировки остаются отдельными событиями.
- Running объединяет агентов, задачи и Apps, поэтому видно реальную работу, а не
  только наличие новых сообщений.
- Полный список остаётся доступен через Conversations и Directory с теми же
  фильтрами, что в варианте A.

## Apps

Running App — такой же источник активности, как работающий агент. Например,
`Export presentation` может завершиться и вернуть результат в Inbox, даже если
App уже закрыт.

Quick Apps остаются глобальными. Из события можно сразу открыть нужный App с
уже переданным контекстом: письмо, файл, preview или результат задачи.

## Mobile

- Основные разделы: **Inbox / Chats / Apps / More**.
- `+` создаёт Quick chat, Task, Agent или Channel / agent group, а также
  открывает App. Новый Agent автоматически попадает в `My Network`.
- Событие раскрывается в соответствующий диалог, задачу, канал или App; назад
  возвращает в ту же позицию Inbox.
- Низкоуровневые настройки networks скрыты в More.
- Важные quick actions доступны прямо у события: Approve, Reply, Retry, Open app.

## Сильные стороны

- Лучшее масштабирование для фоновых и автономных агентов.
- Агенты могут сами собирать временные команды в `My Network`, не нагружая
  владельца каждым новым каналом.
- Пользователь видит работу и исключения, а не обязан читать все чаты.
- Apps, задачи и сообщения объединены в одну модель активности.
- Подходит для большого числа networks без постоянного переключения.

## Риски

- Менее привычно, чем мессенджер.
- Качество UX сильно зависит от приоритизации, mute/digest и отсутствия ложных
  уведомлений, особенно для каналов, которые агенты создают автономно.
- Если большинство агентов просто ждут сообщения, Inbox может выглядеть пустым.

## 4. Сравнение

| Критерий | A — Messenger | B — Spaces | C — Pulse |
|---|---:|---:|---:|
| Близость к понравившимся референсам | Высокая | Средняя | Низкая |
| Быстрый личный диалог с агентом | Отлично | Зависит от space | Хорошо |
| Добавление агента | Автоматически в My Network | Автоматически в My Network | Автоматически в My Network |
| Группировка агентов | Каналы в общем списке | Каналы внутри space | Task channels в Running/Activity |
| Агенты My Network | Recent + Directory | Agents внутри home space | Inbox + Directory |
| Много каналов | Папки и фильтры | Лучший структурный контроль | Digest и Activity |
| Много networks | Фильтры, возможен шум | Лучший вариант | Фильтры, события вместо spaces |
| Автономные фоновые агенты | Activity отдельно | Activity отдельно | Основная модель |
| Простота для нового пользователя | Самая высокая | Средняя | Ниже средней |
| Главный риск | Перегруженный Recent | Лишние переключения spaces | Шумный/непредсказуемый Inbox |

## 5. Рекомендация

Для всех вариантов базовое правило одинаковое: **Add agent → My Network**, а
группировка агентов происходит через каналы, которые могут создавать и люди, и
агенты. Отличается только способ показать эти объекты в ежедневной навигации.

**Основной кандидат для wireframes — A (Fa Messenger)** с двумя заимствованиями,
не меняющими его модель:

1. `Activity` из C остаётся отдельным разделом для фоновой работы и approvals,
   но не заменяет привычный список Chats.
2. `Running / Favorites / Recent Apps` доступны глобально и через quick action,
   а постоянная панель включается только по желанию пользователя.

**B стоит выбрать вместо A**, если networks и каналы — основная ежедневная
работа, а прямое общение с агентами `My Network` вторично. **C стоит выбрать**,
если большинство агентов должны самостоятельно работать в фоне и пользователь
чаще реагирует на
результаты, чем начинает разговоры.

A и B можно проверить двумя наборами wireframes на одинаковых сценариях. C при
этом не теряется: его Activity-потоки ложатся в оба варианта.

## 6. Обязательные сценарии следующего этапа

Независимо от выбранной модели SPA-wireframe должен проверить:

1. Добавить постоянного агента и без дополнительной настройки увидеть его в
   `My Network / Members`, общем поиске и доступных участниках каналов.
2. Позволить агенту создать task-bound канал в `My Network`, добавить трёх
   других агентов, показать creator/назначение и архивировать канал после задачи.
3. Попытаться добавить в группу агента из другой network: получить явный запрос
   разрешения и не открыть доступ к чужой сети автоматически.
4. Начать Quick chat и получить осмысленное название без `New session`.
5. Вернуться к постоянному агенту спустя время и продолжить его основной диалог.
6. Превратить Quick chat в агента с автоматическим membership в `My Network` и
   отдельно связать Quick chat с уже существующим агентом.
7. Найти одного агента среди 118 записей во всех networks и один канал среди 65.
8. Переключиться между `My Network` и пятью дополнительными networks, не теряя
   непрочитанное и черновик.
9. Открыть App из диалога, развернуть fullscreen, вернуться и закрепить панель.
10. Сменить диалог при закреплённом App без молчаливой смены контекста App.
11. Получить результат фоновой задачи через Activity и перейти к источнику.
12. На mobile пройти `Chats → Channel → App → назад` без вложенных drawer и
    дублирующих Back.
13. Проверить пустые, loading, offline, unread, running и failed states.

## 7. Решение перед wireframes

Достаточно выбрать одно из трёх направлений:

- **A** — преимущественно messenger;
- **B** — преимущественно рабочие пространства;
- **C** — преимущественно центр активности;
- либо **A + B для сравнения**, с общими Activity и Apps.

После этого следующий артефакт — кликабельный серый SPA без визуального
дизайна: desktop и mobile, реалистичный большой набор данных и все quick
actions.

## 8. Визуальные направления (styleguide)

Серый wireframe не навязывает визуальный стиль. Отдельная страница
`styleguide.html` показывает четыре полноценных направления для выбора:

- **Liquid Glass** — современный Apple visionOS / iOS стиль: полупрозрачные акриловые панели (frosted glass), зеркальные грани, жидкая пружинная физика, мягкий океанический циан (#38BDF8) на глубоком фоне полуночи (#080A10). Ощущение тактильной роскоши.

- **Folio** — editorial paper & ink: тёплая бумага, чернила, один vermilion
  акцент, Fraunces + Instrument Sans. Для длинного чтения agent-результатов.
- **Graphite** — precision instrument: dark-first графитовая шкала, hairlines,
  IBM Plex Sans/Mono с tabular numbers, один amber signal. Для операторов и
  параллельных запусков.
- **Porcelain** — soft tactile: холодные керамические нейтрали, глубокий
  lagoon teal, крупные радиусы и пружинные переходы. Для массового
  phone-first messenger.

Каждое направление содержит light/dark палитру с вычисляемым WCAG-контрастом,
типовую шкалу, shape/spacing/elevation, 30 hand-drawn SVG-иконок, logo system
(mark, app icon, favicon, wordmark), галерею компонентов со всеми состояниями и
9 replayable motion-демо с указанием длительности, кривой и Flutter-аналога.
Выбор сохраняется кнопкой `Choose this direction`; прямой вход —
`styleguide.html#direction=<id>&mode=<light|dark>`.
